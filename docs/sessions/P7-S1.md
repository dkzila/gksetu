# P7-S1 — QnA Model and Rendering

**Master Plan §43, Phase 7 Session 1** · "Implement `QnA` model and rendering."
*(Opens the assessment layer: the `QnA` entity — explanatory question-and-answer LEARNING content, §23 "explanatory, unscored" — anchored to canonical KnowledgeUnits, riding the full §19 editorial workflow with §36 immutable revisions, rendered as the §22 knowledge page's "Practice — Q&A" layer between learn and revise, savable per §10, and folded into the §17 search surface. The scored `Question` is deliberately NOT here — P7-S2.)*

## Goal

**QnA entries exist as first-class editorial objects and render on the knowledge page.** A `QnA` (§6 row: `knowledge_unit_id, language, question_text, answer_body, status`) is a *representation* of a canonical KnowledgeUnit (§7 — the fact is never re-entered, only rendered as a question + explanatory answer), NOT a scored assessment (§23 — the v2.0 QnA/Question split; conflating them would force explanatory prose into an options/scoring schema it doesn't need, §46.14). It clones the ContentItem discipline exactly: working copy vs live revision (public reads ALWAYS serve the immutable `QnARevision` snapshot), the §19 state machine (DRAFT → IN_REVIEW → SCHEDULED/PUBLISHED → RETIRED with lazy scheduled materialization), §36 corrections append revision N+1 with a mandatory changeSummary, and every transition is audited with §19 editorial-task wiring (objectType `'QNA'`, disjoint from `'ContentItem'`).

## API

| Endpoint | Contract |
|---|---|
| `GET /api/qna/admin?unit=&status=&language=&q=` | Registry list, §38-scoped (ADMIN global; COUNTRY_ADMIN/WRITER global read + own market) + status summary + pagination. |

## Key Decisions

1. **QnA clones ContentItem, it is not a ContentItem format** — §46.14: structurally distinct entities, never collapsed into one generic pipeline. Same §19 machine, same §36 revision discipline, its own table + tasks (`objectType: 'QNA'`) + permission pair.
2. **The question text is identity** (§11): create-time only; re-wording is a NEW QnA (the old one retires) — `@@unique([knowledgeUnitId, languageId, questionText])`; many different questions per unit are the normal §22 layer.
3. **§18 Question/Test-Author rides WRITER** in v1's consolidated four-role model: `qna:manage` narrowed by country + language scope (the content:manage precedent), publish-class gated on `qna:publish`.
4. **Search = fold, not a new object type** (the P6-S3 precedent): QnA text joins the unit's per-language bodyText language-pure; a QnA-only language mints no new document variant (the §35 representation-driven variant rule stands); QnA publications join §17.7 freshness.
5. **A saved QNA reopens the unit's knowledge page** (its §22 layer is the retrieval surface — the CONTENT_ITEM precedent: the §16 unit path in the entry's own language market).
