# P4-S5 — Metadata / Structured Data & SEO Validation

**Master Plan §43, Phase 4 Session 5** · "Implement metadata/structured data and SEO validation."
*(Builds directly on the P4-S4 handoff: the §16 SEO block on every composition, `useSeoHead`, and `GET /api/seo/status` as the validation seed.)*

## Goal

Every public composition now carries a server-built **schema.org structured-data graph** and the SPA ships complete **metadata** (Open Graph, Twitter card, `html lang`) per view, while **`GET /api/seo/status` grows into a live SEO validation surface** — 11 checks over the real sitemap/robots/composition artifacts — rendered on the console's SEO card.

- The P4-S4 layer: `PageSeo` on all five compositions, the segmented sitemap + robots services, `useSeoHead` (the single head choke-point), `getSeoStatus`.
- §16 ("structured data generated where valid: Article, FAQPage where eligible, BreadcrumbList, WebSite, WebPage, Quiz/educational schema types where applicable"), §22 (knowledge page), §33/§34 (landing surfaces), §35 (language honesty), §36 (lifecycle-honest dates), §37 (origin-agnostic DTOs, determinism), §38 (public surface).
- The P4-S4 decision framework: URL-bearing values ship §16 **paths**; every client resolves them against its own origin.

2. **Composition wiring**: `structuredData: PageStructuredData` added to all five compositions (home, topic landing, exam page, syllabus topic, knowledge page). The exam page's graph is identical for a historical `?version=` read — served-but-noindex, every URL still the canonical current surface. 3. **Metadata assets**: `public/og.png` (1216×640 brand card, AI-generated, VLM-verified text rendering) + `public/icon.png` (1024×1024 globe-book mark); `layout.tsx` metadata gains `metadataBase` (env-derived), `icons`, OG/Twitter images.
4. **`useSeoHead` extension** (`seo-head.ts`): Open Graph (title/description/type/url/site_name/locale `ll_CC`/locale:alternate — one element per alternate via a create-only multi-meta helper — image + dimensions/alt), Twitter card (summary_large_image mirror), the **JSON-LD injection** (one managed `application/ld+json` script with `{@context, @graph}`; a recursive resolver prefixes the origin onto `url`/`@id`/`item`/`image` path values), and `<html lang>` tracking (restored on clear). 5. **View wiring**: all five product views pass `language`, `countryIso`, `jsonLd` (+ `ogType: 'article'` on the knowledge reader, gated by the existing `seoInDocument` affordance). The console keeps the default head (`noindex` only).
6. **The validation layer** (`src/modules/seo/validation-service.ts` + `loadSitemapInventory` in the sitemap service): 11 checks over live artifacts —
   - `sitemap-unique-urls` (no path in two segments), `sitemap-path-grammar` (every URL matches its segment type's §16 pattern; the expected locale prefix is taken from the segment's own home URL — never re-derived), `sitemap-no-parameter-urls`, `sitemap-lastmod-honest` (valid, never future), `sitemap-index-parity` (index counts/lastmods vs URL sets vs rendered `<url>` tags — three code paths), `sitemap-determinism` (§37 segment ordering + byte-stable renders), `robots-artifact` (the built text's rule structure, the Sitemap line, and no disallow rule matching any public discovery endpoint), `hreflang-clusters` (self-inclusion, distinct paths, cluster ⊆ country languages, x-default ∈ cluster, **composition↔sitemap parity**: every sampled canonical is the URL its segment lists), `historical-window-noindex` (a started non-current window: noindex `HISTORICAL_VERSION`, clean canonical = the sitemap's current URL), `structured-data-graphs` (WebSite + Organization everywhere with the rendered language, breadcrumb self-closure on hubs, no breadcrumb on home, Article headline/dates/language/image on knowledge pages), `jsonld-path-contract` (every URL-bearing field is a `/`-path).
   - Samples are LIVE compositions (IN/en + IN/hi + GB/en home, IN/hi topic, IN/en exam, syllabus, knowledge page — loaded in parallel via `Promise.allSettled`; a missing sample downgrades the affected checks to `warn`, never a silent pass).

One `loadSitemapInventory()` pass is shared between the census and the validation.
7. **Console** (`seo-section.tsx`): the SEO card gains the validation summary (passed/failures/warnings chips), the full checks table (status icons, checked counts, capped failure samples), and the sampled structured-data surfaces table (locale, §16 path, graph nodes). ## Key Decisions

1. **The JSON-LD graph is server-built data with §16 paths** — exactly the P4-S4 URL model: `url`/`@id`/`item`/`image` hold paths; the SPA head resolves them against `window.location.origin` at injection (a fixed-key recursive resolver), the validation layer asserts the contract. One URL truth, many resolvers — and a mobile client can inject the same graph against its own host.
2. **The WebSite node is the localized site view** (a Hindi page's graph names `/hi/`), while the Organization node is site-global (`/#organization`) — each variant's graph is internally consistent without cross-variant references.
3. **BreadcrumbList closes at the canonical path, from addressable crumbs only** — non-addressable crumbs (the syllabus page's "Syllabus" label) are UI context, not locations; the current page is always the final item.
4. **Article is double-typed LearningResource with the record's own vocabulary** (`learningResourceType` = unit type, `educationalLevel` = difficulty) — honest educational schema, no invented fields; dates mirror the P4-S4 lastmod semantics (first/last published revision shown on the page).
5. **OG/Twitter metadata is presentation (client-composed from title/description + the §16 block)**, while the JSON-LD graph is data (server-composed) — different layers, same facts; `og:locale` derives `ll_CC` from the rendered language + market.
6. **The validation samples the real services, never a parallel truth** — and the seo module still never imports knowledge: the status route (the composition layer) picks the knowledge sample via knowledge's public interface and passes it in as a structural object.
7. **`loadSitemapInventory()`** (one `loadModels()` pass, now parallel across countries) feeds both the census and the validation — 15 segment loads became 1 model walk.
