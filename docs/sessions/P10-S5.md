## The Evaluation

### The measured boundaries (P10-S1, the only evidence this decision may use)

The platform's complete performance profile after the P10-S1 optimisations: the slowest public composition ~2.5s and the slowest ops surface ~4s — every one dominated by the DB round-trip constant (~240–400ms over the sandbox↔Mumbai pooler), not by any module's internal load. Throughput is dev-scale. There is no measured contention between modules, no measured queueing, no measured scaling wall. **Extraction solves problems this platform does not have.**

### The §29/§46.12 triggers — none met

| Trigger | Requirement | Measured state |
|---|---|---|
| Independent scaling | A module's load profile requiring separate compute | Search ~1.0–1.9s over 49 documents; every module shares the same DB-bound profile |
| Team boundaries | Multiple teams needing independent deploy cadences | One implementation agent, one repo, one deployable |
| Domain isolation needs | A module's failure/isolation domain harming others | No cross-module failure has ever escaped the §37 error envelopes |

### The standing protections (why "not now" is safe — the §28 promise)

1. **The boundaries are real and enforced**: 20 logical modules, each with an explicit barrel interface (§28), the direction rule policed in code review discipline (no cross-module internal imports — the per-module duplication precedents document every deliberate exception), and §37 client-agnostic DTOs at every seam.
2. **The extraction surfaces are known and small**: the search module (engine + indexing behind the SearchDocument store — P10-S2's decision record), the assessment engine (the §22 runner), the notifications fan-out (the §27 channel-agnostic dispatch contract — P10-S3's record). Each extracts behind its existing interface without touching the domain model — the §28 test the codebase already passes (the barrels ARE the seams).
3. **The re-evaluation triggers are the §29 table's own**: when a module's measured load (re-run `bun /home/z/e2e/perf-baseline.ts`) shows contention or a scaling wall the monolith cannot absorb, the extraction follows the boundary, not a rewrite.

### The decision

**The modular monolith stands.** No service extraction. The 20-module single-deployable architecture with explicit interfaces is the §28/§46.12/§47 answer at this scale — and the decision's evidence, triggers and extraction surfaces are all recorded so the re-evaluation is a measurement away, never an archaeology dig.
