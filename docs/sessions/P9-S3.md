## What Was Delivered

### 1. The Workspace as a Derived View (§14/§34 — no schema change)

One workspace per configured market. There is NO Workspace table: the market's User rows (homeCountryId) ARE the roster, their languageScopeId rows ARE the language dimension, the board summary is a live groupBy. Every count derives from the same queries the surfaces serve (the launch-checklist twin derivations: `MARKET_UNITS` = GLOBAL-or-owned, §35 per-language page counts). `listWorkspaces(actor)` — ADMIN sees every configured market (paused included, the relaunch-view precedent); COUNTRY_ADMIN/WRITER see exactly their own (fail-closed without a home market). `getWorkspace` adds the roster (COUNTRY_ADMIN → WRITER → platform ADMIN order), per-language coverage (staff able to work it + published pages) and the server-driven `canManage` flag.

### 2. §20 Provisioning (the session's core)

- **Permission**: new `staff:manage` — ADMIN (any market) + COUNTRY_ADMIN (own market, COUNTRY_NARROWED); never WRITER. Route guard + service re-assertion (defense in depth).
- **Invite semantics**: the operator NEVER chooses a password — the server generates a one-time credential (`GlobIQ-` + 13 base62 chars), reveals it ONCE in the response, stores only its scrypt hash. Preferred language = the scope language, else the market default (the seed convention).
- **Adjustments**: role WRITER↔COUNTRY_ADMIN; language scope set/clear (§35-validated against the locale snapshot); status ACTIVE↔SUSPENDED — **suspension revokes every active session immediately** (counted in the audit row; §36 spirit: nothing deleted, reactivation reversible, the credential itself untouched — reset is a separate action); `resetCredential` mints a fresh one-time credential (the old one dies).
- **Refusals, all audited as `staff.denied` (the qnaDenied precedent — a cross-market probe is a security event)**: cross-market reads/writes `403 WORKSPACE_OUT_OF_SCOPE`; by-id probes of another market's staff `404 STAFF_MEMBER_NOT_FOUND` (indistinguishable from unknown — existence never leaks); the platform ADMIN row `403 STAFF_MANAGE_ADMIN_REFUSED` (§38 — visible, never managed through a workspace); self-mutation `409 STAFF_SELF_MUTATION_REFUSED` (operator-to-operator only); `STAFF_SCOPE_ROLE_MISMATCH` 422 (a COUNTRY_ADMIN never carries a language scope — the permission layer only narrows WRITER, so a scope on that class would be a rule we never run; refused at invite AND at promote-time, including the effective-state form).
- **§30 redaction interplay (found in verification)**: the audit layer's redaction masks any key matching /password|…|credential/i to `[redacted]` — the reset flag is therefore named `otpReset` (survives redaction), and the credential note in `staff.create` metadata persists as `[redacted]` by design; no credential material ever reaches the audit trail.

## Verification-Found Fixes (5 — all structural, all found by live verification)

1. **The §20 actor-scope defect (E2E run 1)**: announced-market staff had `actor.countryId = null` (`findActiveCountryByIso` in `actorFromUser`) — fr-admin/writer-fr/uk-admin could not operate their own market. Fix: `findConfiguredCountryByIso` (any lifecycle status) for the staff scope; public self-service keeps the ACTIVE-only rule.
2. **The client-bundle crash (browser round 1 — the P9-S1 SDK-leak class)**: the §32 wiring put `hashPassword` (node:crypto scrypt, module scope) into the client graph through the analytics barrel chain (feedback-section → content-quality → feedback-service → analytics → insights → workspaces barrel). The whole SPA crashed with "The 'original' argument must be of type Function". Fix (two parts, found in two steps): the provisioning split (`provisioning.ts` off the barrel — server-only, route-imported) AND the validation fix (email schema inlined — the identity-access barrel's service pulls password.ts; that barrel must never be imported by a client-reachable module). Verified: SPA renders, 0 page errors, no scrypt module code in the served chunks (only honest mention-strings).
3. **`credentialReset` redacted to `[redacted]` (E2E run 3)**: the §30 redaction layer masks any `*credential*` key — the reset flag vanished from audit metadata. Fix: the flag is named `otpReset` (survives redaction); the finding also upgraded the credential-never-in-audit check to assert `metadata.credential === '[redacted]'` (a stronger guarantee than planned).
4. **B2 — stale cross-user workspace state (browser round 2)**: the section stays mounted through `#/account` identity switches (a scroll target inside ConsoleView); a new actor saw the previous user's selector/forms. Fix: state resets on identity change (`actorKey` effect — every cached view dropped, the load effect refetches). Verified in both directions without reload.
5. **B3 — mobile invite-form overflow (browser round 2)**: the Role select's long option text forced ~517px min-content on the 390px viewport (scrollWidth 558). Fix: short role labels (the §18 nuance moved to description lines) + `min-w-0` on the form grid items. Verified: scrollWidth 390 == viewport.
