# P7-S2 — Question Model and Standalone Practice Mode

**Master Plan §43, Phase 7 Session 2** · "Implement `Question` model and standalone practice mode."
*(The scored half of the assessment layer: the `Question` entity — §6's atomic MCQ object with options/correct_answer/explanation/exam_version_id/difficulty — riding the full §19 editorial workflow with §36 immutable revisions, rendered as the §22 knowledge page's "Practice — Test yourself" scored layer after the P7-S1 Q&A learning layer. Practice is judged SERVER-SIDE: the correctAnswer never ships on the public surface — it is revealed per-question, only after the learner answers. The MockTest/TestAttempt engine is deliberately NOT here — P7-S3.)*

## Goal

**Questions exist as first-class scored assessment objects and the knowledge page has a standalone practice mode.** A `Question` (§6 row: `knowledge_unit_id, exam_version_id, difficulty, type, options, correct_answer, explanation`) is a scored REPRESENTATION of a canonical KnowledgeUnit (§7 — the fact is never re-entered, only assessed), structurally distinct from QnA (§46.14 — never one generic "question" pipeline; §23's v2.0 split: QnA is explanatory prose, Question is options + a key + a teaching explanation). It clones the ContentItem/QnA discipline exactly: working copy vs live revision (public reads ALWAYS serve the immutable `QuestionRevision` snapshot), the §19 state machine (DRAFT → IN_REVIEW → SCHEDULED/PUBLISHED → RETIRED with lazy scheduled materialization), §36 corrections append revision N+1 with a mandatory changeSummary, and every transition is audited with §19 editorial-task wiring (`objectType: 'QUESTION'`, disjoint from ContentItem and QnA tasks). The §6 `exam_version_id` anchor is OPTIONAL authoring context (never identity — §8 routing is ExamMapping's job), validated against the §14 country rule (a COUNTRY-scoped unit may only anchor to its own country's ACTIVE exams).

## Key Decisions

1. **Question clones the QnA DISCIPLINE, not its schema** (§46.14): same §19 machine, same §36 revision discipline, its own table + tasks (`objectType: 'QUESTION'`) + permission pair — but options/correctAnswer/explanation/difficulty per §6, never prose fields.
2. **The correctAnswer never ships pre-answer**: the public practice layer omits it; `POST /api/questions/practice` reveals it per-question, server-judged (§22 "scored assessment"). The admin surface shows the key — authors must see what they publish.
3. **Stateless practice in P7-S2**: §6's TestAttempt ("a user's attempt at a MockTest or Quiz") is the P7-S3 engine that will feed P7-S4 mastery — this session's practice is judged in the moment; no attempt persistence.
4. **The exam anchor is context, never identity** (§6/§8): `examVersionId` is create-time authoring metadata validated by the §14 country rule (COUNTRY units → own-country ACTIVE exams only; GLOBAL units → any), NOT part of the §11 unique — the same MCQ serves every exam whose syllabus maps the unit.
5. **Difficulty snapshots onto the revision** (§36): it is public-facing on the practice layer, so a staged difficulty edit must never leak — publishing freezes it with the rest.
6. **The search fold excludes the explanation**: question + option text is discovery surface; the explanation is post-answer teaching prose (the QnA fold included the answer because a QnA IS the teaching surface — a Question's teaching surface unlocks only after answering).

## Handoff (for P7-S3 — `MockTest` and `TestAttempt` engine)

- The assessment module remains the home; `question-*` files + the QnA twins show the conventions. MockTest is a composed, timed, scoped assembly (§6: title, scope, question_ids[], duration_minutes, pass_criteria, optional exam_version_id) — it REFERENCES published Questions; author it with its own §19 lifecycle + `objectType: 'MOCK_TEST'` tasks.
- `checkPracticeAnswer` shows the server-side judging pattern; the TestAttempt engine (§6: user_id, mock_test_id, started_at, submitted_at, answers[], score, per-question correctness) should reuse the live-revision comparison and will feed P7-S4's mastery + revision queue (§9 implicit signals, §22).
- The practice layer's `PublicPracticeQuestion` DTO is the read model a mock-test assembler can reuse (it already omits the key); admin affordances (`allowedTransitions`) come server-side — the questions-section workspace conventions apply verbatim.
- Seeds to extend: the 8 PUBLISHED questions are ready-made assembly material; §45 expects "a sample MockTest composed from those Questions, plus one sample TestAttempt".
