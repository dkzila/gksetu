## Key Decisions

1. **The queue is computed in the HOME market, always** (§11 step 1 / §14): goal and follow guards are home-market by construction, so the engine call carries the home country; `country`/`language` queries steer LABELS and §16 paths only (the §35 chain shared with the goal GET). `market.isHomeMarket` reports when the browsing context differs.
2. **The engine is imported, never re-derived** (§28): `getCombinedExamView` stays the single §11 implementation; the dashboard owns only the personalisation overlay (scope assembly, subject matching, reasons, tiers). The overlay is the documented P5 merge point the engine's comparator anticipated.
3. **Subject matching expands DOWN the tree only**: onboarding selects nodes at any level, so a selection matches its descendants (Polity & Governance → Fundamental Rights…); ancestors are deliberately not expanded — selecting one child never drags its siblings into a user's "why". The matched reason references the SELECTED subject (label + slug), and duplicate coverings under one selection dedupe to a single reason.
4. **Read-time eligibility, honest visibility forever** (§36): a followed/goal exam that went INACTIVE/RETIRED stays in the signals with its status, is excluded from the queue, and the queue-level note explains — the P5-S1/S3 declaration-time-guard precedent, now on the feed.
5. **Saves are structurally quarantined from ranking** (§10): the saves block is computed by the follow-save module and rendered last, clearly labelled "Retrieval only — never a recommendation signal"; no queue comparator or reason ever reads it. The §31 test proves saves survive signal removal.
6. **Graceful queue degradation**: an `ExamError` from the engine (e.g. a COMING_SOON home market with no public compositions) becomes an honest `queue.note` — the dashboard itself keeps rendering plan/signals/saves. Only auth and explicit-bad-queries are errors.
7. **§16 identity navigation**: the dashboard navigates by canonical paths (server-built in the queue/saves/summaries), parsed back into routes by one generic lenient `openPath` in the app shell — the same grammar as `parseHash`, reusable by any future surface.
