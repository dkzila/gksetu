## What Was Delivered

### 1. The Launch Lifecycle (`src/modules/country-locale/launch-service.ts`)

- **Semantics fixed on the existing enum** (no migration of values): `INACTIVE` = staged/paused (hidden from every public surface, fully configurable), `COMING_SOON` = ANNOUNCED (publicly acknowledged: switcher "soon" tag, homepage coming-soon hero, sitemap quiet state — NOT routable as a market), `ACTIVE` = LIVE (the full §34 surface + exams in the sitemap + search documents + geo-target eligibility).
- **Transitions**: `announceCountry` (INACTIVE → COMING_SOON), `launchCountry` ((COMING_SOON|INACTIVE) → ACTIVE — enforces the hard invariants, stamps `launchedAt` inside the write transaction), `pauseCountry` (→ INACTIVE — hidden, all content/configuration preserved, reversible). The default root market is immune to all three (`DEFAULT_COUNTRY_IMMUTABLE`).
- **Raw status edits are refused**: `PATCH /api/countries/[iso]` with `status` → `409 STATUS_TRANSITION_REQUIRES_LIFECYCLE` pointing at the lifecycle endpoints — the lifecycle is the ONLY way status changes (the readiness gate, the stamp and the lifecycle audit trail cannot be bypassed).
- **`launchedAt`** (`prisma/schema.prisma`): the market's FIRST go-live moment; set once, kept through pause/relaunch — §36 spirit applied to market history. Seeded for India (`2025-01-01`, the root market is live by definition).

### 2. Derived Launch Readiness (§34 — never a stored checklist)

`getLaunchReadiness(iso)` — 8 checks in stable order: 2 hard invariants (default language configured+active+in-set; ≥1 active configured language — blocks launch) + 6 advisory §34 signals (published knowledge pages, published current affairs, active exams, published practice material, editorial workspace staff, timezone — shown, never silently omitted, deliberately non-blocking: launching a thin market is an operator decision the response records). Every count is **language-scoped** (§35): a market's homepage serves only its configured languages, so EN-on-GLOBAL content counts for GB/en but never for FR/fr — each detail string states exactly what was measured. `availableActions` is derived from the current state.

### 3. §15.1 Geo Routing Signal (§31-safe)

- `GET /api/locale/geo-hint` (public, anonymous, nothing stored or logged): reads the standard edge headers (`cf-ipcountry`, `x-vercel-ip-country`, `x-geo-country`) and suggests ONLY a live (ACTIVE) non-default market — an announced-but-not-launched market is never a routing target; the default root market needs no suggestion (it IS `/`). The response carries the §15/§31 contract note.
- **Client first-visit flow** (`src/app/page.tsx`): once per browser — a first visit to the root fetches the hint and, on a suggestion, navigates to that market's home + explains itself via toast ("pick any country from the switcher at any time"); a deep-link arrival is explicit intent (the link chose, no geo fetch); every outcome records the client-side `globiq-market` choice (client-only, like the theme). The deliberate switcher overwrites it (`origin: 'user'`).

### 4. API (§37)

| Endpoint | Method | Auth | Purpose |
|---|---|---|---|
| `/api/countries/[iso]/launch-readiness` | GET | `country-config:manage` | The derived checklist (any status — a paused market is exactly the relaunch candidate) |
| `/api/countries/[iso]/announce` | POST | `country-config:manage` | INACTIVE → COMING_SOON (optional operator note → audit) |
| `/api/countries/[iso]/launch` | POST | `country-config:manage` | → ACTIVE: invariants enforced, `launchedAt` stamped, honest contract + readiness returned, **search index rebuilt** (§17 eligibility is status-derived; a failed rebuild is reported, never thrown — the transition is committed) |
| `/api/countries/[iso]/pause` | POST | `country-config:manage` | → INACTIVE: hidden + preserved + reversible; index rebuilt |
| `/api/locale/geo-hint` | GET | public | The §15.1 first-visit routing signal |
| `/api/countries?include=inactive` | GET | `country-config:manage` | The admin market list (paused markets stay visible to the console that manages their relaunch) |

Rate limits: `geoHintRead` 60/min, `countryLifecycleWrite` 30/min. Audit actions `country.announce` / `country.launch` / `country.pause` (§30) with before/after, the operator note and `launchedWithWarnings`.

## Verification-Found Fixes (4 — all structural, all found by live verification)

1. **The locale snapshot was per-route-bundle in Turbopack dev** (E2E run 1: 13 failures): `invalidateSnapshot()` cleared only the writing route's module instance — the countries list / geo-hint / homepage routes kept serving the pre-launch snapshot for up to the 60s TTL. Fix: the snapshot store lives on `globalThis` (one snapshot + one invalidation per process, the dev-safe singleton pattern) with an epoch guard so a load racing an invalidation never sticks.
2. **B1 — the §15.1 default-choice write raced the effect cascade** (browser: 2/7 fresh visits stored the choice): `geoPhase` was a ref, so a hint resolving after the config/route effects settled never re-triggered the apply. Fix: `geoPhase` is state — the apply runs in both orders. Re-verified 7/7.
3. **B2 — `#/fr/` was unroutable** (pre-existing `parseHash` flaw, exposed by the first live non-en-default market): the language variable was seeded from the default market and never reset when a country slug matched → `{FR, en}` → honest 404. Fix: entering a non-default market resets the language to THAT market's default. The live France homepage now renders.
4. **B3 — stale SPA country config after transitions** (browser): lifecycle changes didn't refresh the shell's in-memory `/api/countries` — the header switcher showed stale states until reload. Fix: the launch panel dispatches `globiq:locale-config-changed`; the shell refetches. Verified in all three directions.
