# P8-S3 — Content Feedback / Quality-Loop Pipeline

**Master Plan §43, Phase 8 Session 3** · "Implement content feedback/quality-loop pipeline."
*(§25: "No knowledge platform can guarantee zero errors at scale — the trust model must include a way for users and editors to catch and correct them quickly." Every public content object gets a lightweight "Report an issue" action creating a ContentFeedback record — factual_error, outdated, translation_issue, other, §25 verbatim; each report routes into the §19 editorial workflow as a triggered CORRECTION task, prioritised by content traffic/importance; resolution tracked (resolved_by/resolved_at) and feeding the §32 editorial analytics; a QUALITY signal — never a personalisation signal, never public ratings, a moderation/correction queue. §44: "A ContentFeedback report on any content object reaches the editorial workflow and is auditable to resolution.")*

## Goal

**The §25 quality loop, closed end-to-end and honest on both sides.** The public action is anonymous-friendly (the §21 ShareEvent precedent — browse-first readers are exactly who catches errors; a signed-in report attributes the row for §31 follow-up and folds duplicates: one OPEN report per reporter × object × reason, a receipt never an error). The report AND its CORRECTION EditorialTask are created in ONE transaction (the P8-S2 atomicity lesson — a routed report can never dangle without its work item), the task scoped to the reported object's §38 workspace (country-anchor → countryId, global → platform) with language inherited from the representation, priority seeded from the reason (FACTUAL_ERROR → HIGH … OTHER → LOW; §25's "traffic/importance" weighting joins with §32 analytics, P8-S4/S5 — stated on the queue). The workspace's editors are notified through the now-wired §27 FEEDBACK_REPORT_RECEIVED trigger (country reports → that country's COUNTRY_ADMINs; global → ADMINs; the reporter never notified about their own report). Resolution is two-way cascading: closing the report closes its task with the same note, and resolving the task (the §19 side) auto-resolves the report ("Closed with the linked correction task: …") — the loop always closes on both sides, every transition audited, terminal states final (§36) with a new report always fileable. Report counts live ONLY on the editorial queue (feedback:manage, §38-scoped server-side) and the reporter's own view — never public pages (§25's no-ratings rule).

## Key Decisions

1. **Anonymous-friendly, attributed when signed in** (§25/§21/§31): §25 says EVERY public content object gets the action — browse-first readers are exactly who catches errors. The public POST never 401s; the per-IP rate limit is the honest spam guard for anonymous (no stable identity to fold on), and the signed-in duplicate fold (one OPEN report per reporter × object × reason) keeps the queue clean without punishing a concerned reader.
2. **One transaction for report + task** (the P8-S2 atomicity lesson): a routed report can never dangle without its §19 work item. The task row is created directly (the `wireContentWorkflow` precedent — system actor, `metadata.auto` audits) rather than through `createEditorialTask`'s editor-only, ContentItem-only validation.
3. **Two-way cascade, one module direction** (§19/§25/§28): report→task cascades inside content-quality (its own transaction); task→report cascades through hooks the editorial service calls best-effort. editorial → content-quality → notifications — no cycle, the same one-way rule every prior module followed. Task CANCEL does NOT dismiss the report (an abandoned work item is not a judged report — the queue keeps it honestly).
4. **The workspace is the audience** (§27/§38): country-content reports notify that country's COUNTRY_ADMINs, global-content reports notify ADMINs, and the reporter is never a recipient (the self-notification honesty rule). No workspace editors → no notification, honestly stated (the task still exists in the queue).
5. **Priority seeds from the reason; traffic weighting stated as pending** (§25/§32): FACTUAL_ERROR → HIGH, OUTDATED/TRANSLATION_ISSUE → MEDIUM, OTHER → LOW today — the queue's stats note says exactly when the traffic/importance weighting joins (P8-S4/S5).
6. **Quality signal, never a rating** (§25/§9/§31): counts live on the editorial queue and the reporter's own view only; the personalisation reset keeps reports (content-quality data, like attempts); the controls surface explains the separation.
7. **Spec-exact reportable set**: the five object types §25 names. Mock tests are assessment configuration, not factual content — honestly out of scope, rejected with a typed 400.
