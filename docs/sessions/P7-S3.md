# P7-S3 — MockTest and TestAttempt Engine

**Master Plan §43, Phase 7 Session 3** · "Implement `MockTest` and `TestAttempt` engine."
*(The composed half of the assessment layer: the `MockTest` entity — §6's "timed, scoped assembly of Questions" with scope (topic/exam/syllabus_node)/question_ids[]/duration_minutes/pass_criteria/exam_version_id — riding the full §19 editorial workflow with §36 immutable revisions, plus the `TestAttempt` engine — §6's "a user's attempt at a MockTest" with started_at/submitted_at/answers[]/score/per-question correctness. The runner is timed and scored SERVER-SIDE: the key never ships pre-submit, the deadline is server-enforced truth, and every submitted attempt is frozen forever — the §9/§22 mastery signal P7-S4 consumes. Combined-exam mock-test scope is deliberately NOT here — P7-S5.)*

## Goal

**Mock tests exist as first-class timed assessment products and learners can attempt them end-to-end.** A `MockTest` (§6 row) is a composed REPRESENTATION of published Questions (§7 — the facts are never re-entered, only re-assembled and timed), structurally distinct from QnA and Question (§46.14/§23's v2.0 three-way split: QnA explains, Question assesses atomically, MockTest composes and times). It clones the ContentItem/QnA/Question discipline: title/scope/language are CREATE-TIME identity (§11 — re-titling or re-scoping is a new test); questionIdsJson/durationMinutes/passPercent are the WORKING COPY; public reads ALWAYS serve the immutable `MockTestRevision` snapshot (the frozen composition, duration and pass criteria); §36 corrections append revision N+1 with a mandatory changeSummary; every transition is audited with §19 editorial-task wiring (`objectType: 'MOCK_TEST'`, disjoint from ContentItem/QnA/Question tasks). The `TestAttempt` engine snapshots THE DEAL at start (served composition, duration, pass criteria — deadlineAt = startedAt + duration as server-side truth; the client timer is only presentation): start (or resume — one IN_PROGRESS attempt per user × test, refresh-safe), submit (server is the only judge: per-question correctness against the questions' live revisions, unanswered scores as incorrect, a 60s grace absorbs network/clock skew, the conditional claim makes double-submits safe), and the immutable answers[]/score record that P7-S4's mastery engine will consume.

## Key Decisions

1. **MockTest clones the Question DISCIPLINE, not its schema** (§46.14): same §19 machine, same §36 revision discipline, its own table + tasks (`objectType: 'MOCK_TEST'`) + permission pair — but scope/composition/duration/pass criteria per §6, never prose fields.
2. **The attempt snapshot-carries the deal** (§6/§36): served composition, duration and pass criteria freeze at start; a later correction of the test never rewrites a running attempt; SUBMITTED attempts are immutable history — exactly the record P7-S4's mastery engine needs.
3. **The server owns time and truth**: deadlineAt is server-enforced (60s grace); unanswered scores as incorrect; the key/explanations ship only in the post-submit result, per-question — the §22 scored discipline at test scale.
4. **One live attempt per user × test with resume**: start returns the existing IN_PROGRESS attempt (refresh-safe); expired attempts sweep to ABANDONED (system-audited) — retakes are free, clutter is not.
5. **The §14 inheritance for compositions**: a test inherits its SCOPE's country (EXAM → the exam's, TOPIC → the topic's) and may only compose GLOBAL-unit questions or its own country's — a test is never more visible than its questions; every question must match the test's language (§35).
6. **Composition health is a first-class admin concern**: one batched query per registry page computes `anchorPublishable`/`anchorBlockReason`; the publish gate re-checks server-side; a stale composition blocks new attempts with an honest 409 while in-flight attempts still complete.
7. **Identity is service-enforced** (§11): scope × language × title with a friendly 409; the nullable scope columns make a DB composite unique unreliable in Postgres (NULLs are distinct) — the slug stays the hard §37 URL identity.

- The runner's result view (AttemptResultQuestion.unit) is the §22 "revise loops back to learn" link — the revision queue (§22) can rank units by recent wrong answers from the same data.

- Seeds to extend: the sample test + attempt are ready-made mastery fixtures; more attempts across users would exercise distribution-shaped mastery (the §22 per-KU state).
