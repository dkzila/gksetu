### 2. The §16 SEO block on every public composition (`page-seo.ts` + `PageSeo`)

One builder — `buildPageSeo({ country, languages, pathFor, noindexReason?, lastModified? })` — emits `{ canonicalPath, alternates, xDefaultPath, robots, lastModified }` as **§16 paths** (origin-agnostic per §37; the sitemap and the document head resolve them against an origin). Wired into all five compositions:

| Surface | hreflang cluster | lastModified |
|---|---|---|
| `GET /api/home` (§34) | all country-configured languages (structural hub) | newest visible VERIFIED unit update |
| `GET /api/topics/{slug}` (§33) | all country languages | newest subtree unit update |
| `GET /api/exams/{ref}/page` (§16) | all country languages | shown window's effectiveFrom |

Key semantics:
- **x-default** = the country's default-language variant when it's in the cluster, else the first alternate by code (single-language knowledge pages).
- **Historical `?version=` reads** (§16 "canonical tags prevent duplicate parameter pages"): the canonical **stays the current window's clean path** and the variant is served with `robots: { index: false, follow: true, reason: 'HISTORICAL_VERSION' }`.

### 3. The segmented sitemap + robots (`sitemap-service.ts` + three routes)

- **`GET /api/seo/sitemap`** — no query → the **sitemap index** (every non-empty segment with its newest lastmod); the full triple `?country=&language=&type=` → that segment's `<urlset>`. Segments: `home` (1 URL per country × language), `topics` (visible topics whose subtree carries ≥1 VERIFIED visible unit — §16 "high-value"), `units` (knowledge pages per language **with published content only**), `exams` (ACTIVE exams; COMING_SOON markets get no exam segment — §14/§38), `syllabus` (topic-linked placements on CURRENT versions). Enumeration is §36/§14-honest throughout; every URL is built by `buildCanonicalUrl` (never concatenated); ordering is deterministic (§37) — default market first, then ISO; language by code; type in fixed order.
- **`GET /api/seo/robots`** — `User-agent: * / Allow: /` + 10 `Disallow` rules for the admin/editor/private namespaces (`/api/audit`, `/api/auth`, `/api/content/admin`, `/api/editorial`, `/api/exams/admin`, `/api/exams/combined`, `/api/knowledge/admin`, `/api/locale`, `/api/search`, `/api/taxonomy/admin`) + the `Sitemap:` line. Public discovery APIs stay crawlable so a rendered SPA keeps fetching its data.
- **`GET /api/seo/status`** — the JSON census (origin, robots rule set, segment list with URL counts + lastmods, urlTotal) powering the console card and seeding P4-S5's SEO validation.
- **Standard crawler locations**: `next.config.ts` rewrites `/robots.txt → /api/seo/robots` and `/sitemap.xml → /api/seo/sitemap`. The scaffold `public/robots.txt` (which shadowed the rewrite — public files are served before rewrites) was **removed**.
- Absolute URLs resolve against the request origin (`x-forwarded-host`/`host` + `x-forwarded-proto`) or the `GLOBIQ_PUBLIC_BASE_URL` override (`resolveSiteOrigin`).
- New typed errors: `SITEMAP_SEGMENT_NOT_FOUND` (404 — unknown country, unconfigured language §35), `SITEMAP_FAILED` (500); `sitemapQuerySchema` rejects partial triples (400, §37 boundary).

## Key Decisions

1. **The SEO block ships §16 paths, not absolute URLs** (§37 client-agnostic) — the sitemap resolves them against the request origin, the SPA head against `window.location.origin`; `GLOBIQ_PUBLIC_BASE_URL` overrides for deployments behind proxies. One URL model, many resolvers.
2. **hreflang honesty mirrors surface structure**: structural surfaces (home/topic/exam/syllabus) exist in every country-configured language (localized chrome + §35 fallback is the design) — the whole language set is the cluster and the sitemap set; knowledge pages only list languages with published representations (the P2-S5 `translations` precedent) — thin canonical-fallback variants never enter the sitemap, and a rendered non-published variant still includes itself (the hreflang self-rule).
3. **Historical `?version=` reads are served-but-noindex with the clean canonical** — one rule covering both §16 clauses (duplicate-parameter canonical + "SEO surfaces stay CURRENT-only"): the variant is readable (§36 history affordance), never its own canonical, never indexed.
4. **Sitemap segments are the enumeration unit** (country × language × type): the index lists only non-empty segments, each addressable and independently cacheable — the §16 segmentation rule at API level, ready for per-segment CDN caching at scale (§29) without a domain-model change.
5. **robots.txt disallows namespaces, not the whole API** — admin/editor/private namespaces are excluded per §16 while public discovery endpoints stay crawlable (a rendered SPA must keep fetching its data; Google's renderer obeys robots.txt).
6. **`/robots.txt` and `/sitemap.xml` are rewrites onto the API routes** — no new route files (the single-app constraint), the standard crawler locations work, and the API paths remain directly addressable.
7. **The sitemap enumerates the production §16 path routes** — this dev shell still serves the SPA at `/` with the hash mirror (the documented P4-S2 sandbox constraint); the per-view head ships canonical + hreflang regardless, and the deployment session (P9-S4 country-specific SEO operations / production routing) wires the path routes. Documented on the console card so the dev artifact is never mistaken for the production URL set.
8. **The knowledge module consumes the seo module's builder via its public interface** (`buildPageSeo`) — the concern stays owned by §28's seo module without a reverse dependency (seo never imports knowledge).
